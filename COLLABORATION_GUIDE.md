# 🤝 Developer Collaboration & Implementation Guide

Welcome to the Secure Audits team! To ensure smooth development, prevent git conflicts, and maintain system security, please follow these guidelines while implementing your features.

---

## 🌿 General Git & Database Rules (For Everyone)

### ✅ DOs:
* **Work Under Investigator Constraints**: You have been assigned the **`Investigator` role** on the system. All features, testing, and UI code you write must run securely and strictly within the limits of this role. Do not implement any privilege escalations, hardcoded backdoors, or attempt to modify your role assignments to Admin.
* **Create a Feature Branch**: Always create a separate branch for your work.
  * Alisha: `git checkout -b feature/object-detection`
  * Apeksha: `git checkout -b feature/audio-intelligence`
* **Test with Local Storage**: In your `backend/.env` file, set `USE_LOCAL_STORAGE=True`. This ensures any files you upload during testing are saved on your local hard drive, protecting our Supabase cloud storage quota.
* **Define Frontend API Calls**: Add your API functions to the frontend API helper in [api.ts](file:///c:/Users/amish/Desktop/Secure%20Audit/audit-frontend/src/services/api.ts).

### ❌ DONTs:
* **Do NOT commit to `main`**: All code must be pushed to your feature branch and merged via a Pull Request (PR) reviewed by the project lead.
* **Do NOT modify `backend/app.py`**: The main backend gateway holds auth, database queries, and audit logs. Do not edit this file. If you need gateway routing, ask the lead to add it.
* **Do NOT commit model weights to Git**: Large neural network weights (`.pt`, `.bin`, `.onnx` files) are too large for Git. Add them to your folder's `.gitignore` and download them locally.
* **Do NOT commit `.env` files**: Never commit your local `.env` containing database credentials or API keys. Only commit changes to `.env.example`.
* **Do NOT upload files to Supabase Storage**: Keep `USE_LOCAL_STORAGE=True` active during your entire testing and development cycle. Do not change it to `False` or push audio/image binary files to the Supabase cloud bucket. Once your models are accurate and the code is pushed to GitHub, the project lead will perform the final Supabase Storage integration testing in their own workspace.

## 💻 How to Run the Commands (Quick Start Checklist)

Open separate terminal windows for each service you need to run:

### 1. Start the React Frontend (`audit-frontend/`)
```bash
cd audit-frontend
npm install
npm run dev
```

### 2. Start the Main API Backend (`backend/`)
```bash
cd backend
python -m venv venv
# Windows:
.\venv\Scripts\activate
# macOS/Linux:
source venv/bin/activate
pip install -r requirements.txt
python app.py
```

### 3. Start the Object Backend (`object-backend/` - Alisha)
```bash
cd object-backend

# Windows:
```
