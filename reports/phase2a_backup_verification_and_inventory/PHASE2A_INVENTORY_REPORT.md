## 4. MISSING-BACKUP LIST AND DISASTER RECOVERY GAPS

1. **`backups/` Directory is Not Gitignored**
   - Inspection of `.gitignore` lines 370–377 shows `backups/` is absent.
   - *Risk:* Binary backups or database SQL dumps could be inadvertently staged and pushed to remote git repositories, exposing sensitive evidence data.
2. **Missing Automated Snapshotting for `blockchain/ganache-data/`**
   - Ganache chain state is currently stored locally in `blockchain/ganache-data/` (7 files, ~1.81 MB). If Ganache is restarted without `--database.dbPath ./ganache-data`, all smart contract registrations are wiped. No automated snapshot mechanism existed before Phase 2A.
3. **No Secondary / Offsite Replica**
   - Both the PostgreSQL database and `backend/uploads/` reside on a single local disk volume (`C:\`). Hardware failure would cause catastrophic data loss.
4. **Microservices Ephemeral State Unbacked**
   - Photogrammetry job outputs in `photogrammetry-backend/jobs/` and temporary OCR caches have no automated backup strategy.

## 7. MIGRATION RISKS AND ARCHITECTURAL SPOFs

### 7.1 Single Points of Failure (SPOFs)
1. **Split Authentication Architecture (Supabase GoTrue vs Local PostgreSQL):**
   - User credentials, password verification (`supabase.auth.sign_in_with_password`), and user profile synchronization depend on an external Supabase project ([`backend/app.py:747`](file:///c:/Users/amish/Desktop/Secure%20Audit/backend/app.py#L747)). If the external Supabase service suffers an outage, local users cannot authenticate to the on-premise system.
2. **Localhost URL Hardcoding:**
   - Database column `evidence.file_url` stores strings with absolute origins: `http://localhost:8000/uploads/cases/...`. If the port, domain, or protocol changes, all existing URLs break.
3. **Public Exposure of Media via Static Mount:**
   - FastAPI `app.mount("/uploads", ...)` allows direct, unauthenticated HTTP GET requests to files if their URL is known.
4. **Network Interface Bindings:**
   - Backend (`0.0.0.0:8000`), Audio (`0.0.0.0:8002`), and Photogrammetry (`0.0.0.0:8004`) listen on all interfaces, allowing LAN traffic to reach microservices without going through authentication gates.

## 8. RECOMMENDED NEXT IMPLEMENTATION PHASE (PHASE 2B)

The transition to private cloud evidence storage must proceed in discrete, reversible steps:

```
[Phase 2A Complete] ──> [Step 1: Additive Schema] ──> [Step 2: Canonical Keys & Pull Supabase]
                                                                     │
[Step 5: Network Hardening] <── [Step 4: Microservice Adapters] <─── [Step 3: Streaming Route Cutover]
```

1. **Step 1: Execute Additive Schema Migration**
   - Apply the non-destructive SQL script [`backend/scripts/propose_schema_migration.py`](file:///c:/Users/amish/Desktop/Secure%20Audit/backend/scripts/propose_schema_migration.py) to add nullable columns to `evidence`:
     - `storage_backend VARCHAR(50)`
     - `storage_key TEXT`
     - `stored_sha256 VARCHAR(64)`
     - `stored_size BIGINT`
     - `storage_verified_at TIMESTAMPTZ`
   - Keep `file_url` and `file_hash` completely unaltered.
2. **Step 2: Canonical Ingestion & Supabase Migration**
   - For all 30 healthy local files: assign canonical storage keys (`cases/{case_id}/{uuid}_{sanitized_filename}`), set `storage_backend = 'local'`, and record verified hash and size.
   - For the 2 legacy Supabase files: safely ingest them into the storage gateway, verify their SHA-256 against PostgreSQL, and store them locally.
   - For the 3 problem records (`e1d6...`, `1bb7...`, and `2229...`): flag their database status as `INTEGRITY_DISCREPANCY` without altering original files or hashes.
3. **Step 3: Route Cutover & Authenticated Streaming**
   - Implement `GET /evidence/{id}/stream` using `storage_gateway.get(evidence.storage_key)`.
   - Update frontend media viewers (`UI.tsx`) to consume the streaming endpoint with JWT authorization headers.
   - Remove `app.mount("/uploads", ...)`.
4. **Step 4: Microservice Adapters**
   - Update OCR, YOLO, and Photogrammetry dispatch routines to retrieve streams/descriptors via `storage_gateway.get()` rather than parsing raw `/uploads/` file paths.
5. **Step 5: Network Interface Hardening & Gitignore**
   - Update `0.0.0.0` bindings to `127.0.0.1` across all microservices.
   - Add `backups/` to `.gitignore`.
